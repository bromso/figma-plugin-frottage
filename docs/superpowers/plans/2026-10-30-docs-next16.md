# Docs App Upgrade (Next 16, Fumadocs 16, Tailwind 4, Serwist) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `apps/docs` to Next 16, Fumadocs 16 with Tailwind CSS 4, and Serwist in place of the webpack-only PWA plugin, with the Pages workflow on Node 24 and the docs app type-checked by `bun run types`.

**Architecture:** Four groups, one commit each, on branch `chore/docs-next-16`: Next 16 alone (old PWA kept alive with `--webpack`), then Fumadocs 16 + Tailwind 4, then the Serwist swap, then CI, type-check and doc text. Implementers edit files and stop; the controller runs `bun install`, the docs builds and anything that loads native binaries, because subagent sandboxes cannot.

**Tech Stack:** Bun 1.4.2 workspaces, Next 16.4.3 (Turbopack), fumadocs-core/ui 16.17.9, fumadocs-mdx 15.4.10, Tailwind CSS 4.3.3 via `@tailwindcss/postcss`, Serwist 9.5.13 (`serwist`, `@serwist/next`, `@serwist/cli`, `esbuild`), Biome 2.6.

Spec: `docs/superpowers/specs/2026-10-30-docs-next16-fumadocs16-design.md`.

## Facts verified against the installed packages (2026-10-30, scratch install)

- **Next 16.4.3 CLI** has `typegen` and `build --webpack`; Turbopack is the default and `next build` refuses a webpack plugin without `--webpack`.
- **fumadocs-ui 16.17.9 exports** used here: `fumadocs-ui/provider/next` (`RootProvider`), `fumadocs-ui/layouts/docs` (`DocsLayout`, `sidebar.collapsible` still a `SidebarProps` option), `fumadocs-ui/layouts/docs/page` (`DocsPage`, `DocsBody`, `DocsTitle`; props `toc`, `tableOfContent`, `breadcrumb`, `footer`, `editOnGithub`), `fumadocs-ui/layouts/shared` (`BaseLayoutProps` with `nav`, `githubUrl`, `links`), `fumadocs-ui/mdx` (default export `defaultMdxComponents`). Search dialog option `type?: 'static'` exists. CSS presets: `fumadocs-ui/css/neutral.css` and `fumadocs-ui/css/preset.css`. `fumadocs-ui/style.css` and `fumadocs-ui/tailwind-plugin` are gone from the export map except a legacy `style.css` file; do not use it.
- **fumadocs-mdx 15.4.10** generates `.source/server.ts` (exporting `docs` via top-level `await`), `.source/browser.ts`, `.source/dynamic.ts` and `.source/source.config.mjs`; there is no `.source/index.ts` any more. The `fumadocs-mdx` CLI imports its Vite entry and fails without `vite` installed, so `.source` is generated with `postInstall()` from `fumadocs-mdx/next` (verified to work under Bun). `createMDX()` from `fumadocs-mdx/next` configures Turbopack loader rules itself.
- **fumadocs-core 16 loader**: `source.getPage`, `getPages`, `getPageTree`, `generateParams` unchanged; a page's file path is `page.path` (the `Page` type extends `SharedFileInfo` with `path` and `absolutePath`); `page.file` no longer exists.
- **Bun 1.4.2 runs workspace `postinstall` scripts** (verified with a scratch workspace). Not used here; the `types` script generates `.source` itself so the result is deterministic.
- **Serwist 9.5.13 configurator**: `serwist()` from `@serwist/next/config` loads the resolved Next config (basePath, distDir) itself, globs `.next/static/**`, `public/**/*` and, with `precachePrerendered` (default true), `.next/server/{app,pages}/**/*.html`, and rewrites manifest URLs to `${basePath}/...` and `/_next/static/...`. `swSrc`, `swDest`, `globDirectory` are the option names (`globDirectory` optional, defaults to cwd). `@serwist/cli` peers `esbuild >=0.25 <1` (optional, needed for `serwist build`); `@serwist/next` peers `@serwist/cli ^9.5.13`. `serwist build [path/to/config.js]` defaults to `serwist.config.js` in cwd. `SerwistProvider` from `@serwist/next/react` takes `swUrl`, `disable`, `register`, `cacheOnNavigation`, `reloadOnOnline`, `options`, and its own types declare `window.serwist`, so `@serwist/next/typings` is not needed (adding a `types` array to tsconfig would also disable automatic `@types/node` inclusion). `defaultCache` is exported from `@serwist/next/worker`.
- The root `docs:build` script is `bun run --filter @repo/docs build` (not a turbo task), so `GITHUB_PAGES=true` reaches both `next build` and `serwist build`.

```ts
/// <reference lib="esnext" />
/// <reference lib="webworker" />
import { defaultCache } from "@serwist/next/worker";
import type { PrecacheEntry, SerwistGlobalConfig } from "serwist";
import { Serwist } from "serwist";

// `injectionPoint` is replaced by the precache manifest at build time.
declare global {
  interface WorkerGlobalScope extends SerwistGlobalConfig {
    __SW_MANIFEST: (PrecacheEntry | string)[] | undefined;
  }
}

declare const self: ServiceWorkerGlobalScope;

// The worker is served at `<basePath>/sw.js`, so its own path gives the base path.
const BASE_PATH = new URL(self.location.href).pathname.replace(/\/sw\.js$/, "");

const serwist = new Serwist({
  precacheEntries: self.__SW_MANIFEST,
  skipWaiting: true,
  clientsClaim: true,
  navigationPreload: true,
  runtimeCaching: defaultCache,
  fallbacks: {
    entries: [
      {
        url: `${BASE_PATH}/~offline`,
        matcher({ request }) {
          return request.destination === "document";
        },
      },
    ],
  },
});

serwist.addEventListeners();
```

Review outcome for Task 3: four findings during controller verification. (1) After the install, `tsc` lost `page.data.body`/`toc`: Serwist pins `zod` to exactly 4.6.5 while fumadocs-mdx needs `^4.6.7`, so Bun's isolated linker resolved fumadocs-core's optional `zod` peer differently in the docs app and in fumadocs-mdx and created two `fumadocs-core@16.17.9` variants whose `Source` types do not unify; declaring `zod ^4.6.7` in `apps/docs` makes both contexts pick the same variant. (2) `SerwistProvider` registers with scope `/` by default, which the browser rejects for a worker at `/figma-plugin-template/sw.js`; `options={{ scope: \`${BASE}/\` }}` fixes it. (3) A `public/sw.js` left by an earlier plain build is copied into `out/` by `next build` and was precached; `globIgnores` in `serwist.config.js` excludes it. (4) The worker sets `precacheOptions.cleanupOutdatedCaches` so returning visitors lose the `workbox-precache-v2` cache from next-pwa (observed locally). Verified in the served export: worker activated with the base-path scope, 52 precached URLs including every docs page, `~offline` and all `_next/static` chunks with the base path, no console errors. Environment note: in this Claude Code session, executing a never-before-run script file through its shebang (the `.bin/serwist` shim, or any new `#!/usr/bin/env node` file) stalls in `/usr/bin/env`'s loader indefinitely, while `node <file>` works; the builds were therefore verified with `node node_modules/@serwist/cli/dist/bin.mjs build`. The repo keeps the standard `serwist build`; CI runs on Linux. If `bun run docs:build` ever hangs at the Serwist step on this Mac, re-run `bun install` from a normal terminal so the files are created outside that process tree.
