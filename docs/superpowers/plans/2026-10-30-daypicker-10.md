# Calendar on @daypicker/react 10 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the shadcn Calendar from react-day-picker 9.14 to `@daypicker/react` 10.0.2 with no visual change, dropping the direct `react-day-picker` and `date-fns` dependencies from the UI package and Storybook.

**Architecture:** Three commits on `chore/daypicker-10`: the dependency swap in two manifests, the two-line component change (import source and the renamed `month_grid` class key), and a patch changeset for `@repo/ui`. Implementers edit files and stop; the controller runs `bun install`, the type-check, tests, lint, the Storybook build and the browser check.

**Tech Stack:** Bun 1.4.2 workspaces, `@daypicker/react` 10.0.2 (re-exports `react-day-picker` 10.0.2, which depends on `date-fns` 4 and `@date-fns/tz`), React 19.3, Tailwind 4, Storybook 10.6, Changesets 3.

Spec: `docs/superpowers/specs/2026-10-30-daypicker-10-design.md`.

## Facts verified before planning (2026-10-30)

- Exact lines: `packages/ui/package.json` has `"date-fns": "^4.4.0",` and `"react-day-picker": "^9.14.0",` in `dependencies`; `apps/storybook/package.json` has the same two lines. `packages/ui/src/components/ui/calendar.tsx:7` is `import { type DayButton, DayPicker, getDefaultClassNames, type Locale } from "react-day-picker";` and line 74 is `        table: "w-full border-collapse",`. No Storybook story imports `react-day-picker` or `date-fns` directly.
- `@daypicker/react@10.0.2` root exports `DayPicker`, `getDefaultClassNames`, `DayButton`, `DayButtonProps`, `Locale` (alias of `DayPickerLocale`, which extends date-fns' `Locale`, so `locale.code` exists), `RootProps`, `WeekNumberProps`, and the `UI` enum whose grid key is `month_grid`; the `table` key is removed in v10. `Chevron` still receives `orientation`, `Root` still receives `rootRef`, formatters return strings.
- `.changeset/` holds only `config.json` and `README.md`; the `fixed` group is `["@repo/ui", "@repo/common"]`.

## Outcomes

- **Task 1.** Lockfile as predicted: `@daypicker/react@10.0.2` with `react-day-picker@10.0.2` nested, `date-fns`/`@date-fns/tz` transitive only, the jalali and hijri trees gone. Quality review confirmed both workspaces link the same store entry (no duplicate React context) and recommended keeping Storybook's mirror dependency.
- **Task 2.** The planned red step was misleading at first: `bun test <file>` from the repo root skips the UI package's happy-dom preload (fails regardless), and inside the package the old import still resolved because `bun install` had left stale `react-day-picker`/`date-fns` symlinks to the 9.14 store entry in `packages/ui/node_modules` and `apps/storybook/node_modules`. After removing those residues (a clean install never creates them) the test fails on the old import with "Cannot find package 'react-day-picker'" and passes on the new one; all checks were rerun on the clean state. Quality review (against the installed v10 types): every `classNames` key is valid and an unknown key is now a type error (`classNames` is `Partial<ClassNames>`; v9 had tolerated `table` and silently dropped it, so `w-full border-collapse` now actually reaches the table); the four component overrides match v10's prop types; `modifiers.*`, `data-*` selectors and keyboard focus behave as in v9. Applied: `month_grid` appends `defaultClassNames.month_grid` like the other keys (dc37da4). Follow-ups left as-is (shadcn upstream): the `WeekNumber` override spreads `week` onto the `<td>`, and the RTL `rotate-180` on the chevrons likely double-flips since DayPicker already flips `orientation` under `dir="rtl"`.
- **Task 3.** `bun changeset status` lists `@repo/common` and `@repo/ui` for a patch.
