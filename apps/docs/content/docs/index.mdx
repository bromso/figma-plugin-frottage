## What is this?

Frottage imports rendered web pages into editable Figma designs. A Chrome extension saves the page as a `.frottage` file, and the Figma plugin turns that file into native layers. The plugin makes no network requests.

## What's included

- **A Chrome extension** that captures a page's layout, text, images, inline SVG, pseudo-elements and shadow DOM, at every size you tick, in one press and one `.frottage` file. Tick Light, Dark or both in the popup, and tick the page's other languages when it has them. Sizes change the layout width only, not the browser's identity
- **A Figma plugin** that opens one or more `.frottage` files, each holding one or more sizes of a page, builds auto layout, vectors, links and readable layer names, and reports what it imported. Files of one page land as a set: one frame per version side by side, each on its own mode of one variable collection, with color, type and spacing variables that change by mode
- **49 UI components** that look native in Figma, themed live from Figma's colors
- **Storybook** for browsing all components interactively
- **Automated testing**, including end-to-end tests of the capture in a real browser
- **CI/CD pipeline** that validates every change
- **Changesets** for version management

## Tokens and themes

On a single-page import, Frottage creates up to six variable collections; a raw one with nothing in it is left out. `Palette`, `Spacing`, `Border radius` and `Typography` hold the raw values, each with one mode, `Base`. Variables are named from the site's own CSS custom properties, with framework prefixes such as `--bs-` removed. `Color Mode` holds semantic variables such as `color/background`, `color/primary` and `color/border`. It has one mode for each theme you tick at capture or in the plugin's Themes choice. With both ticked, it also keeps any other theme the stylesheet defines. Dark is read from a `.dark { … }` block, `[data-theme]` or `prefers-color-scheme: dark`. Every Color Mode color points into Palette. The last collection, `Theme`, has one mode, `Default`, and a variable for each token. Layers and text styles bind to Theme, and Theme follows Color Mode, so switching the page frame's Color Mode recolors the page.

Layers bind to the token their CSS used. A card and the page background stay different in Dark, even when both are white in Light. Where the CSS names none, Frottage uses a variable with exactly the same value if only one has it. Otherwise it leaves the value as it is and counts it in the report. With **Use existing local styles** on, a repeated color that no variable takes is linked to your solid paint style of the same color, if you have one. In the popup, Light is ticked by default. Dark is ticked when the page defines a dark theme in its stylesheet. Otherwise it is disabled and says "This page has no dark theme." If you untick both, Capture is disabled and says "Tick Light, Dark or both." Dark values come from the stylesheet, so there is no second capture. In "What's in this file", a Themes group lists the file's modes, ticked as you chose at capture. Color Mode gets exactly the modes you tick. With only Dark ticked, frames open in Dark. If you leave the ticks alone, the capture's choice stands. Older files keep every stylesheet theme. If the page can't be checked, Dark starts unticked but you can still tick it. Either way, Light holds the light theme's values and Dark the dark theme's. Switch the frame's Color Mode to recolor the page.

On sites without named tokens, Frottage infers a few clearly evidenced roles: background, foreground, border, primary, muted and muted-foreground. Their descriptions start with "Inferred:". Unnamed colors are named by family and lightness step. Near-identical colors stay separate, with a note "Near twin of …".

Repeated shadows become effect styles and repeated gradients become paint styles. Text styles bind size, line height, letter spacing, family and weight to type variables where the site defines them.

These collections sit beside any `<hostname>` collection, and any `<hostname> · Primitives` or `<hostname> · Theme` collection, that an earlier import made. Those stay as they are, and the report says the file has them. A re-import reuses Frottage's own collections. Frottage never edits your styles or variables. When one of its own variables from an earlier import has a different value now, it adds a new one named `name (2)`. Version sets of several widths keep a single collection.

The report lists the Color Mode modes found. If there are none, it says "No theme found in the stylesheet, so Color Mode has Light only." It also lists inferred roles, near twins, raw values left unbound, modes the plan could not create and renamed variables.

## Components

Frottage reads the names of a page's components from its own code: React props, Vue 3 apps and shadcn or Nuxt `data-slot` markers. Framework wrappers such as Radix `Primitive`, `Slot`, providers and portals are skipped. A minified name such as `o` is used only when a `data-slot` gives the real one, and the report says so.

A named component that occurs at least twice on one device frame becomes a Figma component set. The props that change how it looks become variant properties, such as `Variant` and `Size`, and each combination the page showed becomes one variant. A prop that an occurrence lacks counts as `default`, or `false` for a boolean. Frottage makes only the variants the page showed. It does not invent the rest. A component whose props never change its look becomes a plain component.

The text becomes a `Label` property. Where occurrences differ by an icon, you get a `Show icon` switch or an `Icon` swap. Occurrences that match their variant become instances with their properties set, and one set is shared by all the page's device frames. An occurrence whose own size differs, as when its grid row stretches it, is still an instance, resized to fit. So is one whose picture, icon or empty box (a divider, say) has another fixed size, as a card's picture often does on a smaller screen: the instance resizes that layer, and a layer that fills its parent's width goes on filling it. With hover components on, the sets also get a `State` property with Default and Hover, or an `Interaction` property when the set already has a `State` property from the page's props. If two occurrences have the same props but look different, Frottage does not join them, and the report counts them. When you re-import onto the same page (Current page), Frottage adds missing variants only to sets it made itself, never to your own.

"What's in this file" lists them in one line, such as `Components: Button (4 variants), Card`: sets with their variant counts first, then other components.

Frottage keeps only a prop that is a boolean, a number between -10000 and 10000, or a short token-like word of letters, digits, hyphens and underscores. It never reads children, class names, styles, ids, links, event handlers, `aria-*` or `data-*` attributes, apart from the `data-variant`, `data-size` and `data-state` markers. It also never reads props that can hold someone's words, even a single word: `value`, `defaultValue`, `placeholder`, `title`, `alt`, `label`, `text`, `content`, `description`, `email`, `query`, `search`, `initials`, `username`, any prop starting with `user` and any prop ending in `name` or `Name`. A prop whose name holds `=`, `,` or `|` is left out, because Figma variant names can't hold it. The capture and the plugin both enforce this: the plugin refuses a file whose components carry such a prop.

Frottage does not read Svelte code, because Svelte compiles components away, or Angular code, which in production shows only custom-element tag names. Pages built with them keep the components made from repeated custom elements. It also cannot name a component whose name is minified and has no `data-slot` marker.

## Devices and breakpoints

When the popup opens, it reads the page's CSS breakpoints; Capture waits for them, for up to 1.5 seconds. Breakpoints within 2 px of each other count as one. Under the devices, a `Breakpoints` list shows one row per breakpoint range: its name (`sm`, `min 576`, `base`), the width it is captured at, and a checkbox, ticked by default. If a ticked device covers the range, the row shows that device's name, such as Laptop, instead of a checkbox. The list is hidden when the page records no breakpoints. Capture records each device by name, such as Laptop or Tablet portrait, with a nominal height, and adds one extra capture for each ticked breakpoint no device covers.

The plugin shows "What's in this file" before it imports. It lists a Devices group (rows such as `Laptop 1512`) and a Breakpoints group (rows such as `sm 640`, or `min 576` when the name already holds the width), each with a checkbox per row, then a Themes group with a checkbox for Light and Dark, the collections it will make, and a choice of New page or Current page. Once a mode limit is known, it warns when the import would exceed it.

The import adds two collections beside the layered ones. `Device` has one mode per device, with `device/width` and `device/height`. `Breakpoint` has one mode per CSS range: `base`, `sm`, `md`, `lg`, `xl`, `2xl`, or `min <width>` for other widths. It holds `breakpoint/min-width` and `breakpoint/max-width`. The modes show smallest to largest. When a file's mode limit leaves some out, the ones the frames are in are kept first, the widest device's first, so the extra captures' ranges go before any frame's. Each capture is placed by the width the page was laid out at, so a scrollbar doesn't move it into the range below. A value that changes by width, such as a heading size, goes Theme, then Breakpoint, then a raw value for each breakpoint.

Each device becomes one frame. The frames sit side by side in a Section. Each frame is set to its Device and Breakpoint modes. The Section follows the page's Color Mode when the page was captured in Light, so switching the page to Dark switches it; a page captured in Dark opens its Section on Dark. Gradients bind stop by stop, and a theme color at partial strength, such as `from-primary/50`, binds to a translucent version of it (`color/primary-a50`) that switches with Color Mode too. New page switches to the new page as the import starts. A page with no recorded breakpoints uses each device width as a breakpoint. The report lists the Device and Breakpoint modes Figma made, the ones it couldn't, the modes a re-import added, and stylesheets whose breakpoints couldn't be read.

Older files that hold several widths import the same way, with modes named by width. Files captured with an older build that labeled each capture as a theme or language still import the older way.

## Languages

When the popup opens, it looks for the page's other languages. It reads `<link rel="alternate" hreflang>` first, then URL patterns such as `/en/…` and `/sv/…`, then switcher links that carry `hreflang` or `lang`. The reader that finds the most languages wins. When the page lists only its other languages, as many sites do, the page's own language is added from `<html lang>`; an invalid `lang` is ignored. The popup keeps one entry per language: the page's own, else the one in the same region as the page, else one with no region, else the first. A `Languages` group appears only when it finds two or more and can tell which one the page is in. That language is ticked and can't be unticked, and the popup shows up to 8. Each language is named by its main subtag in its own language, such as English or Svenska.

Capture counts every capture, and a line under the button reads, for example, `8 captures: 3 devices × 2 languages, plus 2 for breakpoints`. Every ticked language is captured at every ticked device. The extra captures for breakpoints run in the page's own language only.

Languages on the same site load in the run's own small window, and no new permission is needed. A language on another site asks for access to that site when you press Capture. If you refuse, that language is left out: `Svenska needs access to sv.site.test, so it was left out.` A language page that fails to load, moves to another site, lands back on the page the run started on, or says in `<html lang>` that it is another language is also left out: `Svenska couldn't be loaded, so it was left out.` The tab returns to the page it started on by loading that page again, so its scroll position and any unsaved form input are lost.

In the plugin, texts are paired by their place in the page, and links also by their target. Paired texts bind to STRING variables in a `Language` collection. It has one mode per language, the page's own first. Switching the Language mode on the page's Section swaps the text. Texts inside repeated parts bind too. A text with mixed styling, such as a bold word or an inline link, stays in the page's own language, because Figma restyles a bound text as a whole. Languages always become modes; they never get frames of their own. Texts that don't pair stay in the page's own language.

"What's in this file" has a `Languages` group. The page's own language is ticked and can't be unticked, and the collections line shows `Language <n>`. The report lists what didn't pair:

- `3 texts exist only in Svenska and weren't added.`
- `4 texts have no Svenska version and stay in English.`
- `2 texts with mixed styles stay in English.`
- `<n> texts in repeated parts stay in English.`
- `<n> texts stay in English: the Language collection is full.` Language holds at most 2000 variables.
- `Only 35% of the Svenska page matches English on Laptop.` One line for each device where under 80% of the page's own texts paired.

When a file's mode limit leaves no room for a language, the report says `Not created: …`. A re-import that adds a language to an existing Language collection reports `Modes added: Language …`. With room for only one Language mode, no Language collection is made.

## Good to know

Closing the plugin during an import can leave its styles and variables in the file; the next import reuses them.

Files group by page URL, so files of one page at different URLs import as separate pages. Language captures from one run are tied to their page and import together. Spacing variables come only from custom properties named for spacing.
