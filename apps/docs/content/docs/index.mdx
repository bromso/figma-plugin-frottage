## What is this?

Frottage imports rendered web pages into editable Figma designs. A Chrome extension saves the page as a `.frottage` file, and the Figma plugin turns that file into native layers. The plugin makes no network requests.

## What's included

- **A Chrome extension** that captures a page's layout, text, images, inline SVG, pseudo-elements and shadow DOM, at every size you tick, in one press and one `.frottage` file. Tick Light, Dark or both in the popup. Sizes change the layout width only, not the browser's identity
- **A Figma plugin** that opens one or more `.frottage` files, each holding one or more sizes of a page, builds auto layout, vectors, links and readable layer names, and reports what it imported. Files of one page land as a set: one frame per version side by side, each on its own mode of one variable collection, with color, type and spacing variables that change by mode
- **49 UI components** that look native in Figma, themed live from Figma's colors
- **Storybook** for browsing all components interactively
- **Automated testing**, including end-to-end tests of the capture in a real browser
- **CI/CD pipeline** that validates every change
- **Changesets** for version management

## Tokens and themes

On a single-page import, Frottage creates up to six variable collections; a raw one with nothing in it is left out. `Palette`, `Spacing`, `Border radius` and `Typography` hold the raw values, each with one mode, `Base`. Variables are named from the site's own CSS custom properties, with framework prefixes such as `--bs-` removed. `Color Mode` holds semantic variables such as `color/background`, `color/primary` and `color/border`. It has one mode for each theme you tick at capture or in the plugin's Themes choice. With both ticked, it also keeps any other theme the stylesheet defines. Dark is read from a `.dark { … }` block, `[data-theme]` or `prefers-color-scheme: dark`. Every Color Mode color points into Palette. The last collection, `Theme`, has one mode, `Default`, and a variable for each token. Layers and text styles bind to Theme, and Theme follows Color Mode, so switching the page frame's Color Mode recolors the page.

Layers bind to the token their CSS used. A card and the page background stay different in Dark, even when both are white in Light. Where the CSS names none, Frottage uses a variable with exactly the same value if only one has it. Otherwise it leaves the value as it is and counts it in the report. With **Use existing local styles** on, a repeated color that no variable takes is linked to your solid paint style of the same color, if you have one. In the popup, Light is ticked by default. Dark is ticked when the page defines a dark theme in its stylesheet. Otherwise it is disabled and says "This page has no dark theme." If you untick both, Capture is disabled and says "Tick Light, Dark or both." Dark values come from the stylesheet, so there is no second capture. In "What's in this file", a Themes group lists the file's modes, ticked as you chose at capture. Color Mode gets exactly the modes you tick. With only Dark ticked, frames open in Dark. If you leave the ticks alone, the capture's choice stands. Older files keep every stylesheet theme. If the page can't be checked, Dark starts unticked but you can still tick it. Either way, Light holds the light theme's values and Dark the dark theme's. Switch the frame's Color Mode to recolor the page.

On sites without named tokens, Frottage infers a few clearly evidenced roles: background, foreground, border, primary, muted and muted-foreground. Their descriptions start with "Inferred:". Unnamed colors are named by family and lightness step. Near-identical colors stay separate, with a note "Near twin of …".

Repeated shadows become effect styles and repeated gradients become paint styles. Text styles bind size, line height, letter spacing, family and weight to type variables where the site defines them.

These collections sit beside any `<hostname>` collection, and any `<hostname> · Primitives` or `<hostname> · Theme` collection, that an earlier import made. Those stay as they are, and the report says the file has them. A re-import reuses Frottage's own collections. Frottage never edits your styles or variables. When one of its own variables from an earlier import has a different value now, it adds a new one named `name (2)`. Version sets of several widths keep a single collection.

The report lists the Color Mode modes found. If there are none, it says "No theme found in the stylesheet, so Color Mode has Light only." It also lists inferred roles, near twins, raw values left unbound, modes the plan could not create and renamed variables.

## Devices and breakpoints

When the popup opens, it reads the page's CSS breakpoints; Capture waits for them, for up to 1.5 seconds. If a breakpoint range is covered by no ticked device, the popup says `Also captures … for the … breakpoint(s)`. Capture records each device by name, such as Laptop or Tablet portrait, with a nominal height, and adds one extra capture for each uncovered breakpoint.

The plugin shows "What's in this file" before it imports. It lists the devices and breakpoint captures with a checkbox each, a Themes group with a checkbox for Light and Dark, the collections it will make, and a choice of New page or Current page. Once a mode limit is known, it warns when the import would exceed it.

The import adds two collections beside the layered ones. `Device` has one mode per device, with `device/width` and `device/height`. `Breakpoint` has one mode per CSS range: `base`, `sm`, `md`, `lg`, `xl`, `2xl`, or `min <width>` for other widths. It holds `breakpoint/min-width` and `breakpoint/max-width`. The modes show smallest to largest. When a file's mode limit leaves some out, the ones the frames are in are kept first, the widest device's first, so the extra captures' ranges go before any frame's. Each capture is placed by the width the page was laid out at, so a scrollbar doesn't move it into the range below. A value that changes by width, such as a heading size, goes Theme, then Breakpoint, then a raw value for each breakpoint.

Each device becomes one frame. The frames sit side by side in a Section. Each frame is set to its Device and Breakpoint modes. The Section is set to the captured Color Mode. New page switches to the new page as the import starts. A page with no recorded breakpoints uses each device width as a breakpoint. The report lists the Device and Breakpoint modes Figma made, the ones it couldn't, the modes a re-import added, and stylesheets whose breakpoints couldn't be read.

Older files that hold several widths import the same way, with modes named by width. Files captured with an older build that labeled each capture as a theme or language still import the older way.

## Good to know

Closing the plugin during an import can leave its styles and variables in the file; the next import reuses them.

Files group by page URL, so language versions at different URLs import as separate pages. Spacing variables come only from custom properties named for spacing.
